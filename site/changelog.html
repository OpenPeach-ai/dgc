CLI releases.

0.41.2 ↗2026-09-17
  • Compaction still summarises the model window. The human log keeps sub-agent spawn cards after that summary, and identity chips pin there instead of dumping under the last answer.
  • Child tool steps are kept for the inner agent page. Opening a restored chip shows that log when DGC saved it.
  • Thinking is the same dial as the composer. You can change it while a turn runs; the next model round uses the new level.
  • Asking to see the options picker in full-auto opens the native selector. Auto-approval is not the picker.
  • Asking for a plan or design doc in Auto also offers the native browser page plus a Markdown download. You do not have to ask for a URL. Plan-mode approval is still present_plan.
  • Pair with extension 0.26.1; editor protocol remains v14.

0.41.1 ↗2026-09-17
  • Same specialists, chips, and background wake as 0.41.0. Pair with extension 0.26.0; editor protocol remains v14.

0.41.0 ↗2026-09-17
  • Named specialists on the task tool: explorer maps the tree read-only, researcher writes one findings file, critic reviews that file, and worker implements. After research, the main agent should spawn critic on the findings path unless you asked it to skip review.
  • A task with background true keeps working after the turn ends. The composer stays free. When the child lands, DGC starts a wake turn with its summary so you are not stuck in a blocked turn polling it.
  • Ultra asks the model to background long independent work that does not block the rest of the turn. Permission mode is unchanged.
  • 2 more notes on the release page ↗

0.40.4 ↗2026-09-16
  • CLI 0.40.4 is 0.40.3 with a complete GitHub Release. Mid-turn model switch, viewed-image chips, and turn-scoped agents are unchanged.
  • Pair with extension 0.25.3; editor protocol remains v14.

0.40.3 ↗2026-09-16
  • You can change the model while a turn is running. The round already on the wire keeps its client; the next model round uses the new one. The chat records Switched to <model>.
  • Viewed images always appear as a chip on the tool step that produced them. Click the chip to open the image, even when the current model cannot see it. After switching to a vision-capable model, the next turn can send the pixels.
  • The prompt area lists every sub-agent from the current turn until that turn ends, then the count clears. History stays in the transcript.
  • 1 more note on the release page ↗
past
0.40.2 ↗2026-09-16
  • Explicit requests to choose from test or example options now expose the selector in Auto mode. If the model prints a menu instead, DGC gives at most two tool-use reminders. Common flat option shapes and recommendations with a rationale are normalized without inventing a user choice.
  • Browser documents work in any mode: present_document renders Markdown as a light page with section navigation, tables and a Markdown download. Use browser Print → Save as PDF for a PDF. URLs are loopback-only and last while the DGC process runs; displaying a document never approves execution.
  • Ollama thinking controls now match the model: most models use on/off, GPT-OSS uses low/medium/high, and GLM 5.3 Flash uses low/high/max. Extra High and Ultra map to the strongest supported native tier; DGC instructions still vary by profile. Native tiers do not imply equal capability across models.
  • 3 more notes on the release page ↗
past
0.40.1 ↗2026-09-15
  • Checklist recovery: when a model prints todo arguments instead of using the tool during tracked work, DGC asks up to twice for the actual tool call. Printed JSON never changes task state; if the model still does not comply, DGC says the checklist was not updated. Work after an earlier todo call in the same batch still gets a progress reminder.
  • Tool permission outcomes persist with their results. Reopened editor chats show read-only approval cards with the actual saved rule or denial note, and denied steps stay labelled denied. A later deny policy still wins over an earlier approval.
  • The installer finds Cursor, VS Code and VSCodium in macOS Applications folders even without their shell commands on PATH, and deduplicates editors found both ways. Pair with extension 0.25.1 for direct extension update recovery; editor protocol remains v14.

0.26.1 ↗2026-09-17
  • Requires CLI 0.41.2; editor protocol v14.
  • Restored sub-agents stay with their spawn cards after compaction. A chip without a spawn card is not drawn. Opening a chip shows the child's saved tool steps when they were kept.
  • Settings → General → Thinking is the composer dial and can change while a turn runs.
current
0.26.0 ↗2026-09-17
  • Requires CLI 0.41.0; editor protocol v14.
  • Sub-agents land as coloured identity chips. The mark moves while the agent works and stills when it finishes. Click the chip, or its row, for that agent's page: duration, answer, and files. Child greps and edits stay on that page.
  • A background specialist keeps the agents pill until it finishes. When it lands, DGC starts a wake turn with the child's summary. The parent transcript stays idle while it runs.
  • 1 more note on the release page ↗

0.25.3 ↗2026-09-16
  • Requires CLI 0.40.3; editor protocol v14.
  • Stacked option cards: each choice is its own rounded tile with a radio, a quiet Recommended tag, and Continue instead of Submit.
  • The agents pill keeps every agent from the current turn, then clears when the turn ends.
  • 2 more notes on the release page ↗

0.25.2 ↗2026-09-16
  • Requires CLI 0.40.2; editor protocol v14. Includes direct verified extension recovery, paired CLI recovery, checklist reminders and persisted approval cards from 0.25.1.
  • The composer counts active agents rather than every agent ever started in the chat. Successful agents disappear immediately; failed or stopped agents remain for 30 seconds. Historical tool steps remain in the transcript.
  • CLI updates show progress, reconnect on success and retain the installer’s actual failure in Output → DGC update. Supported Python discovery handles Finder-launched editor environments.
  • 2 more notes on the release page ↗
past
0.25.1 ↗2026-09-15
  • Editor protocol v14; requires DGC CLI 0.40.1. Automatic CLI recovery installs the version required by the extension. A newer CLI offers extension recovery instead of only a protocol error.
  • Check for Extension Updates checks the official release directly for gallery and manual installs. A newer version offers a checksum-verified VSIX installation and optional reload, including when Cursor’s catalog is delayed. Daily background checks respect the user setting and cannot be enabled by a workspace.
  • Saved tool permission decisions reopen as read-only cards. Denied actions retain their denied status; custom saved rules and denial notes remain visible. Compatibility shutdowns use clearer connection guidance.
past
0.25.0 ↗2026-09-15
  • Editor protocol v14; requires DGC CLI 0.40.0. Adds the agents list, model reconnect lines, question cards with a recommended option, thinking labelled by source, and the images the model looked at.
  • A pill under the prompt shows how many sub-agents the chat has started and whether any is working (● 2 agents, ◆ when one needs you). Click it for a live list with a row per agent; a row jumps to that agent's step when that step is present in the loaded transcript. The list comes back when the chat is reopened.
  • A failed model request shows a muted line in the turn that changes in place, such as Reconnecting 1/3 · connection refused by 127.0.0.1:11434, then Reconnected after 1 retry. Click it for the cause, endpoint, HTTP status, each attempt and a hint, with Copy details. When DGC gives up, the error leads with what failed and shows the hint; restarting DGC's own backend reads Restarting the DGC backend.
  • 6 more notes on the release page ↗

0.24.0 ↗2026-09-15
  • Editor protocol v13; requires DGC CLI 0.39.0. Adds background monitors, token usage reports and resuming a turn the backend was interrupted in.
  • Tasks become a row in the bar above the prompt, like the goal: collapsed to Tasks 2/5 with the step in progress, expandable to the full list, remembered per chat, and Clear works while a turn runs.
  • A running command is shown once, on its card; the group header and the activity row no longer repeat it.
