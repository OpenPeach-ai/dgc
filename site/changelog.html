CLI releases.

0.40.0 ↗2026-09-15
  • Security: project-local named agents load only after directory trust, so an untrusted repository cannot choose a sub-agent's host or environment key. Trust granted in an open terminal or editor takes effect without restarting. Isolated tasks and fleet workspaces use the approved source project's definitions.
  • Sub-agents are counted and listed. The status bar shows how many sub-agents this chat has started and whether any is working (● 5 agents · 2 working, ◆ when one needs you, ○ when none is working), and /agents lists each one with its state, task, what it is doing, run time, tool calls and tokens, also while a turn runs. Counts, nested agents and measured metrics survive reopening the chat. A new chat or a clear starts the count again, and a rewind drops the agents started after that point.
  • When a model request fails, DGC says why. A refused or dropped connection, a busy server (429 or an overloaded answer) or a 5xx error is tried again up to three more times, using Retry-After with a 10-second cap, and one line follows the tries in place: Reconnecting 1/3 · connection refused by 127.0.0.1:11434, then Reconnected after 1 retry or Gave up after 3 retries. In the terminal the line opens to the cause, model, endpoint, each attempt and a hint; dgc -p prints one line per try. A wrong key or a missing model is not retried, and the error says what to check.
  • An answer cut off mid-stream is continued from what already arrived, after a backoff that starts at 0.25 seconds and doubles up to 8 seconds, and its line reads Reconnected · continued from the partial answer. Causes, endpoints and errors never show a URL's user:password@ part, query string or fragment.
  • Questions come with a recommendation. When a choice is yours, the model asks up to four questions of two to four options (six at most), and it is asked to describe each option in a sentence and put the one it recommends first. The full-screen terminal starts on the recommended option: digits pick, Space toggles a multi-choice option, ←/→ move between questions, and Esc closes the questions without an answer, which ends the turn and pauses a standing goal instead of letting the model choose. Answered questions stay in their step and come back in a resumed session. Sub-agents and dgc -p are not offered questions, and full-auto still asks only when you ask to choose.
  • Thinking says where it came from: raw from a runtime serving open weights such as Ollama, summarized by Anthropic or OpenAI when the provider sent a summary, hidden by the provider when it sent nothing readable, and no label when DGC cannot tell. The label follows the endpoint's host, API and model, and a local or private host is never labelled summarized or hidden. Short provider summaries between tool calls show inline and muted (/thoughts inline, the default, or /thoughts collapsed), and thinking is saved with the session, so a resumed chat shows the same blocks and labels.
  • The model can look at images, and you see what it saw. With a model that accepts images, view_image looks at a PNG, JPEG, GIF or WebP file of up to 8 MB in the workspace, read_file on an image does the same, and images from MCP tools reach the model too, up to eight per step. A model without vision is told an image exists and never receives it, and an endpoint/model pair that refuses an image receives no more images until its cached rejection expires (up to one hour) or the DGC process restarts. Each session keeps a private copy of its images beside its transcript, at most 256 MB, deleted with the session and copied when you branch it, and the terminal opens an image in your system's viewer.
  • Continue after a killed backend no longer redoes finished tool calls: each call of a batch is saved as it finishes, and a question or plan review that was open when the backend died is kept and handed to the model as unanswered.
  • A refused artifact preview (a page in a dot folder, or plan mode) shows as a failed step instead of nothing, and artifact pages no longer show a favicon 404 in the browser console.
  • In the full-screen terminal, tool cards wrap between words, header included, and the slash menu still shows /todo once you type /todo clear. A sub-agent's own text no longer appears in the main transcript (its result stays on its task card), and Ollama models whose template wraps native thinking in literal <think> tags no longer show the tags.
  • When used with the editor, this release requires extension 0.25.0 and editor protocol v14. Reloading the editor also preserves an answer that is still streaming, without duplicating queued prompts or streamed text.

0.39.0 ↗2026-09-15
  • The backend no longer stops mid-turn on its own. Commands the agent ran shared dgc serve's command pipe; a Node tool such as npm switched that pipe to non-blocking, the next read came back empty, and serve took it for the editor closing and ended the turn as Stopped. dgc serve now keeps a private copy of its pipe and every command it runs reads from an empty input. If the backend ever does stop during a turn, the editor names the cause and offers Continue.
  • Model requests that hang are noticed. After 45 seconds without progress DGC says it is still waiting, a request that stays silent is retried, and a request that never recovers fails with the model and endpoint named, instead of waiting out a 30-minute socket timeout. Long silent reasoning and a local model that is still loading are not mistaken for a stall.
  • Background monitors. When you ask it to watch or wait for something, the agent can start a long-running command with the monitor tool, keep working, and hear about each line it prints: between tool calls while a turn runs, and as a short turn of its own when the chat is idle. /monitors lists and stops them, wake-ups pause after ten in a row without a message from you, and a wake turn never runs a step that needs your approval outside auto mode. A command started with bash in the background now tells the model once when it exits.

0.38.1 ↗2026-09-13
  • The task list has one owner. The todo tool replaced the tool context's list while the agent kept a stale copy, so a new chat could inherit the previous chat's unfinished tasks and a standing goal could accept a completion report over pending work. The context list is canonical now; a replacement is validated as a whole — bounded, row-indexed errors, common status synonyms accepted, over-long text truncated — so a malformed local-model call cannot erase a plan; task text passes session redaction; and a new blocked status lets the model park a step honestly instead of pretending it is pending or done.
  • Finishing with open todos is a visible notice, not a failure. After its two reminders DGC completes the turn and names what remains (blocked steps excluded) rather than ending the turn as an error: a hard stop there would have paused every standing goal at each cycle boundary, made dgc -p exit 1 for finished work, and failed every later turn of a resumed session that still carried an old list. A standing goal whose only open steps are blocked now ends as blocked with those steps named. /todo clear drops a list the model left behind, and the clear is persisted.
  • Editor protocol v12, shipped together with extension 0.23.0: history snapshots carry the checklist, so a resumed or reloaded editor shows the same tasks the backend enforces (the rewind path included), and a clear_todos command backs the editor's Clear button. Also: the offscreen renderer respects the terminal height under TERM=dumb, and the response-cadence instructions that a token-budget squeeze had silently removed are back. And /bg light (alias /bg white), a readable light terminal mode with live switching; default stays inherit.

0.38.0 ↗2026-09-13
  • /diff: every changed file, its counts and its diff, live under the transcript. The focus pane gains a second occupant beside /files: a read-only view of the working tree against HEAD — staged and untracked files included — with +/− line counts per file, the set summed in the header, and a unified diff with new-side line numbers. It re-reads Git every two seconds while open, so the model's edits appear as they land, and it never writes, stages or runs a shell command.
  • Lines you select in a diff become part of your next prompt. Space starts a selection, Enter attaches it to the composer as a fenced diff block headed by the file and line range, and a takes the whole hunk — so "why did you change these two lines?" quotes exactly those two lines and nothing else about the file enters the model's context. Wide terminals show the list and the diff side by side; narrow ones swap between them with Tab.
  • Two documentation pages join the guide: Diff pane, and Checkpoints & rewind — the restore points DGC has taken before every edit all along, /rewind for code and conversation, the editor's Undo, and /branch, written up as one feature. /diff also appears in the keyboard cheatsheet and the slash-command reference; /diff PATH opens straight into one file.

0.37.3 ↗2026-09-13
  • The backend keeps its own crash log. An editor gets dgc serve's stderr on a pipe and may do nothing with it — DGC's own extension dropped every byte of it — and an ACP or third-party front-end owes us nothing at all, so a backend that dies unattended left no evidence anywhere. `dgc serve` now writes ~/.dgc/logs/serve.log itself: start, exit reason, command failures with tracebacks, and a full stack dump of every thread on a segfault, abort or SIGTERM — the deaths that produce no Python traceback at all.
  • Reopening a session no longer pastes your own goal back at you. The agent writes scaffolding into the transcript so the MODEL reads it — the standing-goal reminder, which embeds the entire objective, and the open-todo nudge. Those are user-role messages, so replaying a restored session rendered them as chat bubbles: the whole goal spec appeared as a prompt nobody sent.
  • Scrolling back into the compacted archive is bounded by frame size, not just by row count. A page was clamped to 200 rows of up to 20,000 characters each — about 4MB before JSON escaping, and past the protocol's 4MB frame ceiling once real transcript punctuation is escaped. An over-ceiling page was reduced to an empty one, so scrolling past the summary showed nothing. Pages now fill to a byte budget and report exactly where they stopped, so the next page resumes there.

0.37.2 ↗2026-09-12
  • The backend can no longer emit a frame that gets it killed. A protocol event larger than the 4MB ceiling is refused by the editor as a protocol violation, and nothing measured the WIRE size before sending: a screenshot is capped at 4MB of PNG, which is about 5.6MB once base64 and JSON-escaped, so any screenshot over 3MB breached it. Frames are now bounded at the writer, and a batch of screenshots is split into frames that fit rather than sent as one oversized event.
  • An event too large to send keeps its envelope instead of being replaced wholesale. A frame carrying a correlation id is a question, not a notification — replacing an approval request with a generic error left the editor nothing to answer and the turn waiting on a decision that could never arrive.

0.37.1 ↗2026-09-12
  • DGC is now open source under the Apache License 2.0, replacing PolyForm Noncommercial. It may be used commercially, inside a company and on client work with no separate agreement, and the licence grants the patent rights contributors hold in the work. Its obligations are the ordinary ones: keep the licence and copyright notice with copies, and state significant changes.
  • A standing goal that DGC has stopped retrying is marked blocked rather than left active. Leaving it active was a lie the clock told — the goal card kept counting while nothing was running and nothing was going to run. Blocked stops the clock and carries the reason into the goal review.

Editor releases.

0.25.0 ↗2026-09-15
  • Editor protocol v14; requires DGC CLI 0.40.0. Adds the agents list, model reconnect lines, question cards with a recommended option, thinking labelled by source, and the images the model looked at.
  • A pill under the prompt shows how many sub-agents the chat has started and whether any is working (● 2 agents, ◆ when one needs you). Click it for a live list with a row per agent; a row jumps to that agent's step when that step is present in the loaded transcript. The list comes back when the chat is reopened.
  • A failed model request shows a muted line in the turn that changes in place, such as Reconnecting 1/3 · connection refused by 127.0.0.1:11434, then Reconnected after 1 retry. Click it for the cause, endpoint, HTTP status, each attempt and a hint, with Copy details. When DGC gives up, the error leads with what failed and shows the hint; restarting DGC's own backend reads Restarting the DGC backend.
  • Questions dock in the prompt box. The recommended option carries a Recommended badge and starts checked, options show their descriptions, and Something else… takes your own words. Arrow keys move, digits and Enter pick, Skip leaves a question unanswered, and × closes the card without answering, which ends the turn. Nothing is sent until you act, what you had typed comes back, and answered questions stay in their step after a reload.
  • Thinking is labelled by source, as in Thought for 4s · raw, or Thought for 4s · summarized by Anthropic, with a hover label that explains it. Short provider summaries between tool calls read inline, muted, and Settings → General → Show model thinking offers inline, collapsed or hidden.
  • A step that produced images shows a count; open it for thumbnails, and click one for a viewer with the image's name, size and source, ←/→ between images, Z for actual size, Open file for DGC's stored copy, and Stop while a turn runs. If DGC needs you meanwhile, the viewer says so and Show takes you there. Images come back after a reload.
  • Messages queued behind a running turn, or steering not yet applied, are no longer lost. After DGC: Restart Backend, a window reload or a backend exit they come back as not sent, ready to restore; reloading only the DGC panel keeps them waiting.
  • Reloading the panel while a turn runs or waits on an approval keeps the turn running, with Stop, one card per open request, and a streaming answer continuing in the same turn. A steered turn reopens as the finished turn it was, with one bubble per steering message.
  • An answered permission, plan or MCP card ends with what was decided (Allowed once, Always allowed with its rule, Denied with your note, Kept planning) and drops its note box. A refused artifact preview shows as a failed step, and in a narrow panel the goal row leaves out an objective it has no room for.

0.23.1 ↗2026-09-14
  • Editor protocol v12, unchanged from 0.23.0: this release only changes how a version mismatch is resolved. A CLI older than the extension is now updated automatically, with a progress notification you can cancel, and the panel reconnects by itself. Editors update extensions on their own, so the old prompt reported a mismatch the user had not caused. Turn it off with dgc.autoUpdateCli.
  • A dgc.command you set yourself is never reinstalled over; that case still asks first.
  • The installer refuses to extract a release over a git checkout, so no update can revert uncommitted work in a contributor's tree.

0.23.0 ↗2026-09-13

  • One session checklist above the composer, with a Clear button, replaces the task card per turn: it never scrolls you away from what you were reading, restores with the session, empties with a new chat, and shows blocked steps distinctly.

0.22.4 ↗2026-09-13
  • A finished goal stops being a pinned goal: a completed objective stayed on the rail with a play button, so the obvious next click resumed work that was already done. Paused and blocked goals still offer Resume.
  • The backend's log survives when nobody is watching — an output channel only reaches disk once opened, which is never the case for an unattended run. stderr and the exit reason are also appended, timestamped, to backend.log in the extension's log directory.

0.22.3 ↗2026-09-12
  • When the backend dies you can now find out why: its stderr was forwarded to a webview message type nothing handled, so every traceback was silently discarded. It goes to a DGC Backend output channel now, with the exit code or signal beside it.
  • A killed backend is distinguished from one that stopped cleanly — the line collapsed both, because exit code 0 is falsy in JavaScript and the signal was thrown away at the listener.
  • The panel recovers on its own when its backend dies, and a goal interrupted that way picks itself back up; the goal clock stops instead of counting against a dead process.
  • 2 more notes on the release page ↗

0.22.2 ↗2026-09-12
  • The panel recovers on its own when its backend dies. dgc serve is a plain child of the extension host, so an extension update or a window reload takes it down — and the panel kept pointing at the dead process until someone found DGC: Restart Backend. It now starts a replacement itself, bounded to three restarts in two minutes.
  • A goal interrupted by that death picks itself back up, while a goal you paused yourself is never revived behind your back.
  • In auto mode the model pill takes the auto colour instead of staying purple inside an olive composer.
